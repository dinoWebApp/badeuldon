# RULES.md — 받을돈 스티키 강제 규칙

긴 대화·컨텍스트 압축 후에도 유지되어야 하는 규칙이다. 규약(HARNESS_CONVENTION.md)과 충돌 시 규약이 우선한다.

1. **승인 게이트**: 오케스트레이터는 사용자 승인 전 에이전트를 스폰하지 않는다(§6.13). `progress.json` `currentPhase=awaiting_approval` 상태에서는 플랜 재보고 후 승인 대기한다.
2. **개발 작업 라우팅**: 기능 구현·수정·리뷰·테스트·디버깅 요청은 반드시 `badeuldon-orchestrator` 스킬로 처리한다. 오케스트레이터는 코드를 직접 수정하지 않고 Developer 에이전트에게 위임한다.
3. **일회성 스폰**: 모든 에이전트 위임은 task tool로 신규 스폰한다. 완료 보고한 에이전트 재소환 금지(§4.6).
4. **문서 선행**: PRD.md 갱신은 구현보다 먼저(Phase 2). "수정 사항 없음" 불허 — 최소 버전/날짜 갱신이라도 기록.
5. **Rule ID 필수**: 비즈니스 규칙 변경은 PRD의 Rule ID로 기록한다. ID 재사용 금지.
6. **경로 불변**: `.omp/progress.json`과 `_workspace/` 위치를 변경하지 않는다.
7. **품질 게이트**: `bin/ci`(RuboCop 0에러 + Brakeman 0경고 + 테스트 통과) 없이는 완료 보고할 수 없다.
8. **KST 고정**(TIME-1): 일정·발송 로직의 시간대는 대한민국 표준시만 사용한다.
