# 01_plan.md — 인증 정책 반전: OAuth 폐기 → 아이디/비밀번호 + 랜딩 반영

- **일자**: 2026-10-12
- **pipelineType**: Full (Phase 0→1→✋→2→3→4→5→7→8→9)
- **도메인**: F-AUTH (PRD §6.1) + F-SURF/F-LP(랜딩 반영) + F-EXT(의존성 표)

## B. 구현 범위 (Phase 3 Developer — `rails g authentication` 기반)

1. **인증 골격** (Rails 8 표준 generator 산출물 기반):
   - User 모델(`email` 고유, `password_digest`) + 마이그레이션 + bcrypt(Gemfile 주석 해제)
   - 회원가입·로그인·로그아웃(세션) — generator 표준 + 회원가입 화면
   - 비밀번호 재설정(AUTH-8) — 메일러 산출물 포함(발송 서비스 미지정이므로 개발 로그 발송, 실 발송은 EXT 확정 시)
   - `Authentication` concern(before_action 가드) — 표면 ②(` /app`) 진입 가드 준비
2. **랜딩 반영**:
   - 주 CTA 문구 PRD 확정문으로 교체 + **회원가입 화면으로 실제 링크 연결**(SURF-4 단일 진입점 — 이제 href 활성화)
   - 기존 랜딩 테스트 7건 중 CTA 비활성 검증(SURF-4 `<a>` 0개)은 링크 활성화로 **수정 불가피** — Tester가 Rule 변경에 맞게 갱신
3. **후속 제외 명시**: AUTH-1.3 최초 프로필 설정 화면(표시명·사업자 유형·계좌), /app 대시보드 뼈대 — 별도 작업

## D. 리스크·모호점 (승인 전 결정 필요)

1. **랜딩 CTA 문구 확정** 필요 — 제안: **「무료로 시작하기」+ 보조 문구 「무료 · 카드등록 없음 · 3분」유지**(카카오 언급만 제거). 다른 문구 원하면 지시 바램
2. 이메일 **발송 서비스가 미지정**(EXT 표) — 비밀번호 재설정 메일은 개발 환경 로그로만 발송됨. 실발송은 서비스 선정 작업에서 연결
3. 이메일 인증(가입 시 이메일 확인 링크)은 Rails 표준에 미포함 — **미제공**(기존 '이메일 인증 링크 방식 제공 안 함' 정책 스펙상 자연 소멸되나, 재확인 필요시 지시)
